gallant - check files against rules with a decision model

Usage:
  gallant [options] path...
  gallant [options] --diff
  gallant [options] --assume-filename name

Description:
  gallant checks files against rules. A rule gives one question to a decision
  model, and gallant prints one line for each answer. Rules are markdown files
  in .agents/gallant.

Input:
  With no --diff or --assume-filename, gallant checks the files and directories
  you name. An explicit file is always checked. A directory is walked, and each
  file whose name matches a rule is checked; hidden files and directories (names
  beginning with a dot) are skipped during the walk.

  --diff reads a unified diff from standard input and checks each changed file.
  --assume-filename reads one file from standard input and names it, so a pipe
  can stand in for a file. The two options are mutually exclusive and take no
  path operands.

Options:
  --provider name         model provider (default $GALLANT_PROVIDER or "opencode")
  --model name            model name (default $GALLANT_MODEL or the provider's)
  --rules dir             directory of lint rules (default $GALLANT_RULES or ".agents/gallant")
  --jobs n                files to check concurrently (default 8, at least 1)
  --include-passing       also print the rules the file passes
  --json                  print the answers as a JSON array
  --diff                  check a unified diff read from standard input
  --assume-filename name  check one file read from standard input under this name
  -h, --help              print this help and exit

Output:
  gallant prints one finding per line in a fixed, space-separated format:

    <file> <rule> <type> <confidence> <result>

  The format is line-oriented: every newline is escaped, so one finding stays on
  one line. For machine consumption, --json prints an array of objects instead:

    gallant --json

  A file that cannot be checked (for example, one too large for the model) is
  reported on standard error as "gallant: <file>: <reason>". The other files are
  still checked, and the run exits nonzero.

  A failure of the provider itself (an unreachable or erroring server) is
  reported once, not per file.

  If the rules directory holds no rules, a warning is printed and nothing is
  checked.

Environment:
  GALLANT_PROVIDER  default model provider, used when --provider is absent
  GALLANT_MODEL     default model name, used when --model is absent
  GALLANT_RULES     default rules directory, used when --rules is absent

  A flag overrides its environment default. An environment variable set to the
  empty string counts as unset.

Exit status:
  0    all checks ran and none failed
  1    a check failed, or an error stopped the run (for example, a missing API
       key, an unreadable rules directory, or a provider that could not be
       reached)
  2    the command line cannot be used: no input, conflicting options, an
       unknown provider or model, or an invalid option value
  130  the run was interrupted

Examples:
  gallant .
  gallant main.go pkg/handler.go
  git diff HEAD~1 | gallant --diff
  printf 'package main\n' | gallant --assume-filename main.go
  gallant --provider ollama --model nimble --jobs 16 .

Help topics:
  gallant --help rules      the rule format
  gallant --help providers  the provider list
