gallant - check files against rules with a decision model

Usage:
  gallant [options] path...
  gallant [options] --diff
  gallant [options] --assume-filename name

Description:
  gallant checks files against rules. A rule gives one question to a decision
  model, and gallant prints one line for each result it reports. Rules are
  markdown files in .agents/gallant.

Input:
  With no --diff or --assume-filename, gallant checks the files and directories
  you name. An explicit file is always checked. A directory is walked, and each
  file whose name matches a rule is checked; hidden files and directories (names
  beginning with a dot) are skipped during the walk.

  --diff reads a unified diff from standard input and checks each changed file.
  --assume-filename reads one file from standard input and names it, so a pipe
  can stand in for a file. The two options are mutually exclusive and take no
  path operands.

Options:
  --provider name         model provider (default "opencode")
  --model name            model name (default from the provider)
  --rules dir             directory of lint rules (default ".agents/gallant")
  --jobs n                files to check concurrently (default 8)
  --include-passing       also print the rules the file passes
  --json                  print the findings as a JSON array
  --diff                  check a unified diff read from standard input
  --assume-filename name  check one file read from standard input under this name
  -h, --help              print this help and exit

Output:
  gallant prints one result per line in a fixed, space-separated format:

    <file> <rule> <type> <confidence> <result>

  Confidence is the probability of that result, the same for every rule type.
  Every outcome the model weighed is printed: fail and pass for a noul, every
  option for a choice (most likely first), and every level for a score (most
  likely first). A noul is reported only when its probability of a violation
  clears minConfidence, or when --include-passing is given.

  A choice or score whose rule declares a violation condition prints a verdict
  line before its outcomes:

    <file> <rule> <type> fail (useless 0.95 > 0.5)

  The parenthetical names the clause that decided the verdict. A passing
  verdict is printed only with --include-passing, like a passing noul.

  The format is line-oriented: every newline is escaped, so one result stays on
  one line. For machine consumption, --json prints one object per finding:

    {"file": "a.go", "rule": "comments.md", "type": "choice",
     "verdict": "fail", "reason": "useless 0.95 > 0.5",
     "results": [{"result": "useless", "confidence": 0.95}]}

  Every object has file, rule, type, and results. verdict and reason appear
  when the rule declares a violation condition.

  A file that cannot be checked (for example, one too large for the model) is
  reported on standard error as "gallant: <file>: <reason>". The other files are
  still checked, and the run exits nonzero.

  A failure of the provider itself (an unreachable or erroring server) is
  reported once, not per file.

  If the rules directory holds no rules, a warning is printed and nothing is
  checked.

Exit status:
  0    all checks ran
  1    an error stopped the run
  2    no input, or conflicting options
  130  the run was interrupted

Examples:
  gallant .
  gallant main.go pkg/handler.go
  git diff HEAD~1 | gallant --diff
  printf 'package main\n' | gallant --assume-filename main.go
  gallant --provider ollama --model nimble --jobs 16 .

Help topics:
  gallant --help rules      the rule format
  gallant --help providers  the provider list
